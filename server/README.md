# 미깡메모 AI 서버

Node.js 24에서 프로젝트 의존성을 설치하고 실행한다. 서버와 앱 소스는 같은 버전을 사용한다.

1. 서버 환경에 운영자의 `OPENAI_API_KEY`를 비밀 값으로 등록한다. `MEMO_DB`에는 영구 저장 볼륨의 SQLite 파일 절대 경로를 지정한다. 예를 들어 `/var/lib/memo/usage.sqlite`를 사용할 때는 상위 폴더를 먼저 만든다.
2. 프로젝트 루트에서 `node server/index.js`를 실행한다. 기본 주소는 127.0.0.1:8787이다. 앞단에 HTTPS 리버스 프록시를 연결한다. 컨테이너 환경에서는 필요에 따라 HOST와 PORT를 설정한다. 모든 요청은 같은 원장을 사용하는 서버로 보낸다.
3. 배포할 앱의 `electron/ai-service.json`에 공개 HTTPS 주소를 origin으로 입력한 뒤 기존 빌드 절차로 패키징한다. 개발 실행에서는 MEMO_AI_ORIGIN으로 지정할 수 있다. 이 주소에는 인증정보를 넣지 않는다.
4. 같은 MEMO_DB 환경에서 `node server/index.js issue customer-001`로 이용 코드를 발급한다. 구매자별로 고정된 식별자를 사용한다. 출력된 코드를 해당 고객에게 전달하면 설정 → AI 연결 → AI 이용 코드에서 등록할 수 있다. 같은 ID로 재발급하면 이전 코드는 만료되고 사용액은 유지된다.

## 캘린더와 날씨

운영 서버의 비밀 환경 변수에 `KMA_SERVICE_KEY`를 등록한다. 공공데이터포털의 **기상청_단기예보 조회서비스**(`VilageFcstInfoService_2.0`) 인증키를 사용한다. 설정 → 날씨에서 도시를 선택해 실황과 오늘·내일 예보를 확인한다. 지원 도시는 server/kma.js의 시청 격자 목록에 있다.

Google Cloud에서 발급받은 **데스크톱 앱** OAuth JSON은 서버의 비밀 파일로 올리고 절대 경로를 `GOOGLE_DESKTOP_OAUTH_FILE`로 지정한다. 비밀 파일을 지원하지 않는 호스팅은 `GOOGLE_DESKTOP_OAUTH_JSON`에 JSON 내용을 등록한다. Google Calendar API를 활성화하고 테스트 중에는 사용자의 Google 계정을 테스트 사용자로 등록한다. 공개 배포 전 민감 권한 검증을 완료한다. 서버는 인증 코드를 토큰으로 교환하고 기기는 갱신 토큰을 OS 보안 저장소에 저장한다. 일정 조회는 기기가 Google에 직접 요청한다.

Windows에서 로컬 테스트하려면 기존 앱을 트레이에서 종료한 뒤 프로젝트 루트에서 `npm run start:integrations`를 실행한다. 파일 선택 창에서 OAuth JSON을 고르고 터미널에 날씨 인증키를 입력한다. Node.js 24와 프로젝트 패키지가 필요하다. 테스트 서버는 127.0.0.1에만 열리고 앱 종료 시 함께 종료된다. 상용 빌드는 ai-service.json의 HTTPS origin을 사용한다.

월 한도는 한국 시간 기준 1달러다. 서버는 호출 전에 최대 예상 비용을 원자적으로 예약하고, 응답의 입력·캐시·출력 토큰으로 정산한다. 응답이 유실되어 청구 여부를 확인할 수 없는 요청은 예약액을 유지한다. 한도 부족 시 앱은 로컬 정리를 사용한다. 단가는 표준 GPT-4.1 mini의 100만 토큰당 0.40 / 0.10 / 1.60달러 기준이다. 공급자 가격이나 모델을 변경할 때 서버 단가와 이미지 토큰 상한도 함께 갱신한다. 원장은 사용자 식별자, 코드 해시, 월별 사용 금액을 보관한다.
